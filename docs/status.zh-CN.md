## 尚未发布的客户端修复

会话界面和 controller 操作现共用纯 Java 的设备凭据权限规则。只读配对会说明发送通知需要
`notify` 范围；收件会话允许通知不代表设备有发送权限。master 连接未声明视频支持时，
即使主机没有发送相机帧，也会显示缺少视频能力的提示；替换连接会清除旧协商状态。
通知探针改为必须指定专用 ambient/keepalive 测试收件会话，并保存唯一标记和只发送一次的记录。

本地签名 Release 构建、331 项 JVM 契约及 618 条国际化/源码检查通过。
一次 API 35 预设相机状态的界面短检查通过 14 项，未开启采集，包含没有相机帧时显示提示、
声明视频支持后清除提示。
这些修改尚未包含在公开 Preview 2 中。一次真人语音消息/可听回复及通知实际收件已在本地原包 E2 通过。

## 尚未完成与优先级

| 优先级 | 未完成/未验收 | 下一步需要什么 |
| --- | --- | --- |
| P0 实际使用 | 完整免按键 ambient 自然对话及长期后台恢复仍未验收 | 本地原包 E2 已通过一次实际真人语音消息/可听回复；没有相关需要时，不重复或扩大这项检查 |
| P1 服务能力 | 真实到访未验证；指定会话的通知收件已在本地原包 E2 通过 | 到访需要有定位/geocoder 的设备；通知断连不确定性与更多目标/平台属于后续验证 |
| 暂缓：Sight | 用户于 2026-11-15 明确暂缓；实现保留，真实协商/上传仍未验收 | 用户明确恢复且房间服务提供媒体能力后再继续，不自动检查发布状态或修改房间服务 |
| 后续设备接入 | 目标带屏智能音箱尚未到位；厂商阵列/AEC/后台限制、遥控或无触摸体验未实现或未验证 | 确定 Android/API/ABI/输入能力；标准路径先验证，有差异再增加 adapter，不修改业务页面 |
| 后续兼容 | 不含 ARMv7/32 位；并非全部 OEM、外接屏/折叠屏和权限/生命周期组合都已验证 | 有实际需求再增加 ABI/窗口或硬件验证 |
| 后续维护 | Android controller 仍较大，存储与系统服务仍在 app 模块 | 按业务 owner 渐进拆分；协议与尺寸/硬件边界已建立，不为抽象新增空模块 |
| 暂缓 | Android Push 注册/relay/receiver，以及 AES-GCM/HMAC/ledger 与上游向量；外接 Passport 蓝牙 | 用户后续明确恢复该范围 |
| 旧版迁移限制 | 旧包与公开包不能共享私有数据库/AndroidKeyStore；没有跨包数据迁移器 | 显式同包名/同签名构建保留原节点与数据；独立安装公开包时才需要自己的登录与配对 |

智能音箱支持目前是可复用架构与标准 Android 路径，不是目标硬件已经验收。远场唤醒词、kiosk/常驻 launcher、系统级后台和厂商私有播放引擎也不在本次实现中。完整 1:1 差异继续保存在 [migration.md](migration.md)，不以预览版版本号暗示功能等同 iOS。
