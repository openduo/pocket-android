## E2 录音恢复与触屏反馈

公开包名迁移时，通用 APK 曾覆盖 E2 阵列构建。固件 04319 的标准录音入口虽能打开，却收不到有效
麦克风信号。现在已用同签名、公开包名的本地阵列 APK 覆盖恢复，保留数据与配对。voice／natural
两种模式的本地校准均通过原生阵列录到播放的校准音，结束后释放麦克风，不上传或发送录音。
另以通用包通过不可用保护检查：给出本地化原因、产生零个音频包并释放资源；耳机麦克风仍保留
标准路由。此结果确认采集入口恢复，不新增真人 ASR 准确率结论。

触屏、实体键和无障碍操作共用录音面板，动画表示录音状态。触屏长按时按钮位置固定；非触屏发起的录音在同一面板显示发送和取消。[E2 定向输入检查](input.zh-CN.md#有限验证)使用注入事件和真实采集，只向 Try 发送，随后原配对房间恢复在线。

显式固件构建单独输出本地 `dist/Pocket-E2.apk`，不覆盖用于通用发布的 `dist/Pocket.apk`。
E2 必须保持适配 APK，厂商库／模型不能进入公共发布资产。见[音频证据](audio.md#e2-built-in-capture)
与[本地构建](devices.zh-CN.md#e2-案例)。

## 共享 Rust 协议接入

[pocket-rs](https://github.com/openduo/pocket-rs)：配对／Endpoint、Chat／文件／朗读／live 请求、
语音分帧、实时事件校验、Ambient 输入／播放及重试规则实际执行 Rust。原对应 Java 状态机已替换，
门面保留既有领域 API。UI、SQLite 事务、凭据／Tailscale 网络、编解码／硬件资源和前台服务仍属
Android。OutboxSender／RoomLink 负责平台副作用顺序，不会同时驱动第二个 Rust 聚合 Session。

签名／数据／配对／节点。16 条 Rust／ART 检查与 22 条 Try 文字／预制语音／文件／朗读／重连
检查通过；另有 15 条真正熄屏的静音播放检查通过。此次不采集麦克风、不向真实房间发送测试内容。
设置／草稿恢复，原房间恢复 Online。Preview 3 包含这项接入及后续媒体下行修正。此项证明共享协议接线，不代表 APP

## 锁屏语音回复中断修复

接收／播放生命周期现与 Activity 可见性分离；会话服务通过 `mediaPlayback`、CPU 局部唤醒锁和

有限空闲期限。具体边界见[架构](architecture.zh-CN.md)及[音频证据](audio.md#finishing-an-ongoing-reply-while-locked)。

修复后的签名通用 APK 通过 API35 的 15 项短息屏检查：实际锁屏后接收新音频包，6 秒静音音频在同一

Debug／Release、源码／650 条国际化检查及公开双 ABI payload 检查通过。未使用麦克风、真实房间

15 条息屏播放验证，原房间恢复 Online。
当时的新包使用标准 Android framework 音频；上面的 E2 录音修正随后在同一公开身份恢复本地阵列
适配。早期真人语音验收仍保留原构建身份。

## 所有权拆分与停止点

本轮把草稿／引用／附件及编辑确认移到 `:core/Composer`，有限历史分页移到 `:core/HistoryPager`，
live 代次／队列／最后控制帧移到 `:core/RoomLink`，可取消的上传／下载任务移到
`:core/AttachmentTransfers`。Android `AttachmentStore` 只提供文件存储操作。
`:app/TailnetSession`、`:app/Microphone` 和 `:app/RoomPlayback` 分别拥有授权、采集及播放生命周期；
`ConversationComposer` 把编辑器／IME／附件状态与会话列表分开。所有者共用 controller 的 state
executor，controller 不重复保存已拆出的状态。

检查剩余 controller 和较大的生产类后，本轮拆分到此停止。配对／Try／凭据切换、数据库接纳、
音频焦点、权限和前台服务的执行顺序继续由应用协调层负责；已有功能组件、事务存储及按 key
更新的列表渲染保留内聚边界。没有新增空模块、运行时容器或大而全的转发接口。具体理由见
[所有权表与停止点审查](architecture.zh-CN.md#停止点与所有权审查)。

最终轻量 JVM 检查通过 2,615 项，其中新增 38 项可控顺序契约，覆盖草稿／导入提交、有限历史与
迟到的当天初始化、live 代次／最后控制帧，以及附件独立取消／结果接纳。通用 Debug 与同包名本地
E2 Release 构建通过；源码／国际化检查覆盖 143 个生产 Java 文件、646 条 catalog。通用双 ABI
APK 已确认仅包含公开 native payload。

最终覆盖安装的原包 E2 通过 24 项短联调：预制 Try 文件导入／上传／下载、编辑器到草稿的确认、
文字／预制语音发送、原生静音播放／排空／取消、live 重连，以及短暂真实采集后取消且不发送录音。
最后原房间恢复 Online，配对和草稿保留，回复音频、静音与输入选项恢复。没有向真实房间发送测试
内容，也没有重复人声、通知、相机、旋转或长期后台矩阵。精确入口为
`POCKET_LEGACY_IDENTITY=1 POCKET_TEST_COORDINATION_ONLY=1 POCKET_E2_TEST_CAPTURE=1 scripts/test-device.sh`，
需设置目标设备的 `ANDROID_SERIAL` 并使用匹配的本地构建／classpath。Preview 3 已发布这项重构；
上述设备证据保留当时本地原包构建的身份。

## 发送与朗读流的所有权拆分

输入重构后，`:core/OutboxSender` 继续拆出当前 HTTP 发送、固定语音字节／参数、请求注册、重试预算、
取消和有界发送 worker；`:core/SpeechReader` 拥有朗读身份、流分包／取消和当前结果接纳。
`:app/ReadAloudOutput` 负责流线程上的解码器与共享播放接入。数据库事务、前台服务、音频焦点及
房间副作用仍由 controller 在同一个 state executor 上协调，不再保留第二套发送／朗读请求编号，
也没有设备专属发送实现。交接顺序见[架构文档](architecture.zh-CN.md)。

新增 71 项可控时钟／执行顺序的契约，覆盖提交失败前不发送、迟到／未授权结果、固定重试身份与字节、
语音／Passport 预算、worker 占满后恢复、分包／取消、解码器所有权及播放排空身份。完整轻量 JVM
检查共 2,577 项通过。通用 Debug、原包名本地 E2 Release 构建通过，保留的设备探针全部编译通过；
源码／国际化检查通过，覆盖 646 条 catalog、135 个生产 Java 源文件。

一次原包名 E2 短联调通过 14 项：仅向 Try 发送文字和预制语音、真实静音 Opus／AudioTrack 播放与
排空、共享停止／取消，并恢复原房间 Online，保留配对与草稿。没有录音或向真实房间发送测试内容，
没有重复人声、通知收件、实体键或广泛机型／生命周期测试。该检查点使用本地原包，Preview 3
已发布这项重构。精确入口为
`POCKET_LEGACY_IDENTITY=1 POCKET_TEST_COORDINATION_ONLY=1 scripts/test-device.sh`，
需设置目标设备的 `ANDROID_SERIAL` 并使用匹配的本地构建／classpath。

在这一历史检查点，连接／重连、草稿／附件／历史及环境音频仍在 controller。上方本轮跟进已拆出
其中独立的状态／资源，并记录了其余应用执行顺序保留在一起的原因。
