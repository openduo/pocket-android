# 按键、遥控器与统一动作

[English](input.md) · 简体中文

触屏、无障碍激活、键盘和前台实体键共用应用动作。E2 是随项目提供的具体案例，业务层不识别
E2 型号、Android 键码或屏幕尺寸。本次实现晚于 Preview 2，尚未包含在该公开 APK 中。

## 如何验证灵活性

验收标准是更换输入来源或设备时不复制房间业务。E2 检查既覆盖默认键位，也验证公共扩展能力：

| 变化 | 扩展位置 | 已有证据 |
| --- | --- | --- |
| 新增一个前台按键 | 在设置学习该输入设备的映射 | 用方向／确认键将收到的 F3 绑定为「打开设置」，随后该键正常打开页面 |
| 改变同一按键的交互 | 选择另一个 `InputAction` | 将录音键从切换模式改为按住／松开，不修改源码 |
| 混用触屏与实体键 | 共享 `InputTarget` 和有所有权的 `VoiceNotes` | 触屏清理不能结束实体键录音，明确的发送／取消仍可操作当前录音 |
| 屏幕不能触摸 | 原生焦点导航和公共面板 | 方向／确认／返回能进入设置、完成学习和选择动作 |
| 增加其他 OEM | `DeviceAdapter.keyAction` 与必要的驱动实现 | 源码／模块边界检查已建立，目标音箱实际硬件仍待验收 |

最后一项是已建立的架构扩展路径，不代表第二款硬件已经验收。输入适配器不拥有房间状态、上传队列或
独立麦克风。下面的 E2 键位只是这套公共能力的例子。

## E2 的使用方式

| 操作 | 默认行为 |
| --- | --- |
| 录音键（`F1`，Android 131） | 按下并松开后开始录音，再按一次发送 |
| MARK 键（`F2`，Android 132） | 正在录音时取消；其他时候停止语音播报 |
| 屏幕录音控件 | 按住录音、松开发送，移出取消；按钮保持原位，显示录音动画、时长和松手提示 |
| 录音面板 | 实体键／确认键／无障碍录音保留明确的发送和取消按钮；触屏按住时隐藏 |

开始录音会进入对话页，展示麦克风准备与录音状态。触屏的简单动画只在实际采集启动后显示，
不读取实时音量，也不需要向任何方向滑动发送。确认键／无障碍激活可开始或发送。
文本输入模式下也可直接用实体键录音，原草稿
保留。E2 键位来自设备适配器和已有固件按键记录，不写进房间协议。通用 Android 的 `MEDIA_RECORD`
也默认执行语音开始／发送。

进入 **设置 → 按键与遥控器 → 添加或修改按键**，按一下要配置的键，再选择动作。映射按 Android
输入设备描述符、键码和扫描码保存，重启后保留，并覆盖设备默认值。列表支持重新分配、移除映射和
禁用动作；移除覆盖后恢复适配器默认值。系统只有扫描码的按键，只要向窗口派发事件，也可学习。

可分配：按住录音／松开发送、开始／发送语音、仅发送当前录音、取消录音／停止播报、切换环境模式、
切换回复静音、朗读最新回复、打开对话、打开设置及不执行动作。单独的发送动作不会开启下一段录音。

映射只处理系统实际派发给前台 Activity 的按键。方向、确认、返回、Home、电源和音量等保留系统／
导航用途；编辑文字时，字符键和带修饰键的快捷键正常传递。固件或系统服务已经消费的按键无法在这里
学习。本实现不接管后台全局按键、默认启动器或系统媒体按键。

## 无触摸操作

方向键或 Tab 移动原生焦点，确认／Enter 激活，返回键返回页面或关闭面板。公共按钮与输入框使用
填充色突出焦点，设置开关以整行作为一个焦点。页面在当前窗口内记住焦点，按键学习和动作选择面板
同样可以使用保留的导航键操作。

地图和图片在普通焦点状态下不会吞掉方向键。按确认进入移动模式，方向键移动视口；再次确认或返回
先退出移动模式，然后恢复页面导航。地图缩放按钮仍可聚焦，移动模式内可用键盘 +/- 缩放。选中颜色和双语提示区分
移动模式与普通焦点。

这提供了可复用的带屏智能音箱前台输入与导航方案。目标音箱的真实键事件、音频路由、授权和厂商焦点
行为仍需硬件到位后确认；远场唤醒词和系统级常驻能力不在本次实现中。

## 扩展边界

输入经过 `InputBindings + DeviceAdapter` 解析为 `InputAction`，再由 `KeyGestureRouter` 和
`InteractionDispatcher` 转交应用动作；触屏控件直接使用同一个 `InputTarget`。

- 纯 Java `:input` 只定义动作、目标和按键边沿规则，不依赖 Android、业务或设备模块。重复事件不多次
  切换，松手按最初绑定处理；焦点丢失后的取消事件不能变成点击，丢失松手事件也不会永久卡键。
- `:device` 的 `DeviceAdapter.keyAction(keyCode, scanCode)` 提供默认值，`:device-e2` 单独声明
  录音／MARK 映射。其他适配器返回同一组动作，不引用 controller 或页面。
- `app/input` 管理 Android 事件、本地映射和权限提示。`InteractionDispatcher` 将业务动作交给
  state executor，将导航交给 host。授权完成后提示重新操作，不自动恢复已经结束的录音手势。
- `:core/VoiceNotes` 拥有唯一录音的身份、输入来源、字节、就绪状态及持久化恢复。controller 协调
  capture，并通过 `Store` 进行入库。触屏松手只结束自己开启的录音；明确的发送／取消可结束当前录音。
- `FocusNavigation`、`Ui`、`ViewportNavigation` 负责焦点和显示。窗口失焦、切页和 Activity 停止会
  取消该窗口的前台录音，不会自动发送。

新增动作按用户意图命名；不要把型号或键码加进业务 reducer，也不要在 View 中维护另一套麦克风／
录音状态。controller 仍协调网络、outbox 和音频，后续拆分应沿实际所有权边界进行。

## 有限验证

JVM 契约覆盖重复、取消、修改绑定、丢失松手、输入来源、持久化交接和房间／Try 隔离。E2 短检查
注入 Android 按键事件、使用真实原生采集、只向 Try 发送，最后恢复自定义映射和原房间在线：

```sh
ANDROID_SERIAL=YOUR_DEVICE_SERIAL \
POCKET_TEST_INPUT_ONLY=1 POCKET_E2_TEST_CAPTURE=1 \
scripts/test-device.sh
```

先安装相同签名的[E2 本地阵列构建](devices.zh-CN.md#e2-案例)。2026-11-17 的导航构建在 E2 上通过 44 条检查，
涵盖触屏与 REC 共用录音面板、长按控件位置固定、一次松手只向 Try 发送一条、占位文字居中，
以及打开／收起／结束环境模式。录音或发送任务进行中不能运行。
这不代表用户已经实按录音／MARK，不代表真实遥控器／智能音箱验收，也不重复真人语音验收或启动
无关的 UI／后台矩阵。当前结果见[状态文档](status.zh-CN.md)。
